스프링 API 강의 정리

게터·세터가 뭔지 → 왜 필요한지 → hello-api가 실제로 어떻게 돌아가는지 순서로 보시면 됩니다.

1. 게터 / 세터

값을 넣는 문(set)과 꺼내는 문(get)

private을 붙인 변수는 클래스 바깥에서 직접 건드릴 수 없습니다. 그래서 값을 넣고 꺼낼 수 있는 메서드를 따로 만들어 두는데, 이게 세터와 게터입니다.

바깥 코드Controller 등
→
setName("spring")값 넣는 문
→
private name금고 (직접 접근 불가)
→
getName()값 꺼내는 문
→
"spring"돌려받은 값
2. JS와 비교

사실 JS에도 같은 개념이 있습니다

Java (강의 코드)

static class Hello {
    private String name;

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }
}

Hello hello = new Hello();
hello.setName("spring");
hello.getName();  // "spring"
hello.name;       // 에러 (private)

JS로 똑같이 쓰면

class Hello {
    #name;   // # = private

    getName() {
        return this.#name;
    }

    setName(name) {
        this.#name = name;
    }
}

const hello = new Hello();
hello.setName("spring");
hello.getName();  // "spring"
hello.#name;      // 에러 (private)

JS에서는 보통 hello.name = "spring"처럼 바로 넣지만, Java는 변수를 private으로 숨기고 get/set 메서드로만 다루는 게 일반적인 규칙입니다. this.name = name은 "이 객체의 name(왼쪽)에 매개변수로 받은 name(오른쪽)을 넣는다"는 뜻입니다.

3. 이번 강의에서 왜 필요했나

Spring이 JSON을 만들 때 getName()을 씁니다

핵심: /hello-api가 {"name":"spring"}을 돌려줄 수 있는 건, Spring이 Hello 객체 안의 getName()을 찾아서 호출하기 때문입니다. 메서드 이름 getName에서 get을 뗀 name이 JSON의 키가 됩니다. 게터가 없으면 Spring은 private name을 볼 수 없어서 JSON을 제대로 만들지 못합니다.
4. hello-api 전체 흐름

localhost:8080/hello-api?name=spring 을 열면 일어나는 일

  1. 브라우저
    주소창에 /hello-api?name=spring 입력
  2. Spring
    @GetMapping("hello-api")가 붙은 helloApi 메서드를 찾아 실행. @RequestParam("name")이 주소의 name=spring을 꺼내 변수 name에 넣음
  3. 내 코드
    new Hello()로 빈 객체 생성 → setName("spring")으로 값 넣음 → return hello
  4. Spring
    @ResponseBody가 붙어 있으니 HTML 템플릿을 찾지 않음. 대신 Hello 객체의 getName()을 호출해서 JSON으로 변환
  5. 브라우저
    화면에 {"name":"spring"} 표시
5. 이번 강의 3가지 방식 비교

@ResponseBody가 있냐 없냐의 차이

방식코드 특징return 값의 의미브라우저 결과
MVC@ResponseBody 없음"hello-template" = 화면 파일 이름Thymeleaf가 만든 HTML 페이지
API (문자열)@ResponseBody 있음"hello" + name = 그대로 보낼 글자hellospring
API (객체)@ResponseBody 있음hello 객체 = JSON으로 바꿀 데이터{"name":"spring"}

실무 감각으로 보면 API(객체) 방식이 가장 중요합니다. 지원하시는 팀 업무인 쿠팡이츠·카카오 같은 외부 연동이 전부 이렇게 JSON을 주고받는 방식입니다.

추천

지금은 이것만 이해하고 넘어가셔도 됩니다

  1. private 변수는 get/set 메서드로만 넣고 꺼낸다
  2. @ResponseBody가 없으면 return 값은 "화면 파일 이름", 있으면 "그대로 보낼 데이터"
  3. 객체를 return하면 Spring이 게터를 이용해 JSON으로 바꿔 준다

게터·세터는 다음 강의(회원 관리 예제)에서 계속 나와서 반복하다 보면 자연스럽게 익숙해집니다. IntelliJ에서 변수만 쓰고 Cmd + N → Getter and Setter를 누르면 자동으로 만들어 줘서 직접 칠 일도 거의 없습니다.
